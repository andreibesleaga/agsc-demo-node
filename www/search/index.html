    Every published item

    • Advanced Architectures: Larger agent systems built by combining simpler patterns, such as a research system with a lead agent and parallel searchers.
    • Agent-Graph Optimization: Treat an agent workflow as a graph of nodes, edges and prompts, and search that space with an evaluator, as GPTSwarm, AFlow and MASS do.
    • Agent Identity and Scoped Credentials: Give each agent its own identity and short-lived, task-scoped credentials so delegation narrows authority and actions are attributable.
    • Agentic Supply Chain Integrity: Sign, pin and allowlist the models, tools, protocol servers and prompts an agent loads, and keep a way to revoke any of them at once.
    • Agents as Tools: Wrap a specialist agent as a tool, so a calling agent can hand it one bounded task and keep control.
    • Anti-Patterns: Common mistakes in agent systems, how to recognise them, and how to avoid them.
    • The Augmented LLM: A language model enhanced with retrieval, tools and memory that it uses actively, described by Anthropic as the basic building block of agentic systems.
    • The Autonomy Ladder: A six-level scale for how much an agent may decide alone, chosen per kind of action from risk, not from model capability.
    • Blackboard: Independent specialists work on one problem through a shared workspace; a control step picks who contributes next.
    • Bulkhead Isolation: Give each agent, tenant or dependency its own bounded resource pool, so a fault or overload in one stays out of the others.
    • Canary and Shadow Deployment for Prompts and Models: Release a changed prompt or model to a small share of live traffic, or to a copy of it, and compare it with the current version before promoting.
    • Card format: What a card of this node must hold, stated so that tasks can follow it and a check can test it.
    • Check a card against its sources: Compare one card with the public sources it cites and propose the result.
    • Classical Foundations: Established software patterns, such as the saga, applied to agent workflows.
    • Cognitive & Behavioral: Ideas from cognitive science, such as self-monitoring, turned into agent patterns.
    • Curiosity-Driven Curriculum: Choose an agent's next task from novelty or learning progress instead of a fixed task list, as in Voyager's automatic curriculum.
    • Data & Retrieval: How agents find and use the right information, and how to measure whether they did.
    • The Deep Research Loop: Split a question into parts, search them in parallel, combine the findings and check that every claim has a source.
    • Dual-LLM Pattern: Keep the model that can act away from untrusted text: a tool-less model reads it, and plain code passes results between them.
    • Error Analysis by Open and Axial Coding: Read traces, write open notes, then group them into a failure taxonomy, so the categories come from the data.
    • Ethics & Sustainability: Human control over autonomous systems, and their effects on people and the environment.
    • Evaluation & Testing: How to test agents and measure whether they work.
    • Evolutionary Prompt Search: Improve prompts by keeping a population, letting an LLM mutate and recombine it, scoring on a training set and keeping the fittest.
    • Exception Handling and Recovery: Classify each failure, retry short faults with limits, switch route for lasting ones, and report reduced results honestly.
    • Foundational: The basic building blocks of agents, such as loops, tools and ways of combining model calls.
    • Future Research: Open research questions about agents, with what is known and what is not.
    • Generative Agents: A simulated character with a full memory record, reflection over it, and plans drawn from both, so it stays consistent over days.
    • Given/When/Then Agent Specs: Write agent requirements as Given/When/Then scenarios and run each as a repeatable evaluation.
    • Global Workspace as Blackboard: Specialist modules share one workspace, with specialised processors around it, as in Global Workspace Theory.
    • Goal Setting and Monitoring: Give an agent a goal with checkable criteria, then monitor its progress and decide to continue, re-plan or stop.
    • Golden Trajectories and Snapshot Tests: Store a known-good agent run as a test case and replay it on each change; Google's ADK and Anthropic describe tolerant ways to compare the results.
    • Governance & Accountability: Records, rules and checks that make agent actions accountable.
    • Graph of Thoughts: Model LLM reasoning as a graph of thoughts and dependencies, so thoughts can be combined and refined, not only branched.
    • Human-Only Merge Gate: An agent works on its own branch and cannot approve or merge; a named human decides what reaches the main branch.
    • Idempotency Keys for Agent Actions: Attach a stable idempotency key to each side-effecting call so a retried or replayed request is executed once, as Stripe and Temporal describe.
    • Tamper-Evident Agent Audit Log: An append-only, hash-linked record of every important agent action, so what happened can be rebuilt and checked.
    • Judge Calibration: Measure an automated judge against human labels before trusting its verdicts, and audit it for position, verbosity and self-enhancement bias.
    • Keep cards short: The decision that each card says one thing under each heading, in one sentence.
    • Meaningful Human Control: Two conditions for real human control: the system responds to relevant human reasons, and its actions trace to a person who understands it.
    • Memory & Cognition: How agents remember, forget and turn past work into reusable skills.
    • Memory and Context Poisoning Defense: Treat writes to agent memory and retrieval stores as untrusted: validate, attribute, segment and expire entries, following OWASP ASI06.
    • Metacognitive Monitoring and Control: A meta level watches how sure the agent is while it works and decides to continue, retry or abstain.
    • Multi-Agent Debate: Several model instances propose answers, read one another's responses and revise over rounds; a judge or convergence ends the debate.
    • Operations & Reliability: Running agents in production, including handling failures, controlling cost and watching behaviour.
    • Outcome-Based Pricing: Charge for achieved outcomes such as a resolved conversation instead of seats or usage, which requires agreeing criteria for the outcome upfront.
    • OWASP Top 10 for Agentic Applications: OWASP's list of ten security risks for agents that act, a shared vocabulary for threat models and security reviews.
    • Parallelization: Run independent subtasks at once and combine the results, either by splitting the work or by running the same task several times.
    • Pass^k Reliability: Score an agent by the probability that all k repeated trials of a task succeed, rather than at least one.
    • Plan Approval Gate: The agent researches and proposes a plan without editing source; a person approves, changes or rejects it before edits start.
    • Product Practice: Product decisions for agents, such as how much an agent may do on its own.
    • Prompt-Caching Layout: Put the stable prompt prefix first and variable content last so provider prompt caches can reuse it on later requests.
    • Protocols & Interop: Shared formats and addresses that let agents, tools and organisations work together.
    • Publish gate
    • Reasoning & Decision: How agents set goals, decide what to do next and know when to stop.
    • Record–Replay for Agent Tests: Record real model responses in one test run and replay them from a cassette on later runs, so tests run offline and repeat exactly.
    • Reference Architectures: Complete agent designs that combine several patterns into one working system.
    • Resolution, Containment and Deflection Metrics: Separate deflection, containment and resolution, and state how 'resolved' is verified, as Intercom, Zendesk and Sierra define it.
    • Retrieval Evaluation: Measure whether retrieval found the right material separately from whether the answer used it faithfully.
    • Safe Interruptibility: Design agents so a human stop is honoured and the agent does not learn to avoid or seek interruption.
    • Saga for Agent Workflows: Give each important agent step an undo action, so a failed multi-step run can be rolled back instead of left half done.
    • Agentic SDLC: Building software with agents through phases, approval gates and reviews.
    • Security: Threats to agents, and the designs that defend against them.
    • Shadow-Mode Rollout: Run an agent on live work with its side effects suppressed, then compare its proposed actions with what people actually did.
    • Skill-Library Compounding: Store verified procedures so an agent's skills build up across tasks instead of being rediscovered every run.
    • Specification Gaming: Agents optimise the criterion you wrote, not the result you meant; the gap between the two is where failures hide.
    • Specs & Requirements: How to state what an agent should do when its behaviour is not fully predictable.
    • Agent as State Graph: Express an agent as nodes, edges and shared state run in super-steps with checkpoints, as in LangGraph and Google's Pregel model.
    • Sustainability Signal Plane: A well-known URI where a system publishes its energy and carbon figures, and reads its peers' figures as input to its decisions.
    • Re-check the sources of a card: Open each source of one card, confirm that it still says what the card says, and record the date.
    • Report a source that no longer answers: Tell the node about a source address that fails, with the name of the card that cites it.
    • Termination and Exit Conditions: Define in advance each way an agent loop ends, such as a final answer, a turn limit, or a pause for human input.
    • Thinking-Budget Control: Set how much reasoning a model spends per task class before the call, using effort levels and thinking settings that providers document.
    • Multi-Agent Topologies: Ways for several agents to work together, such as a shared workspace or a hierarchy.
    • Trajectory and Outcome Evaluation: Grade the end state an agent produced and the path it took as two separate questions, each with a suitable grader.
    • Unbounded Loops: An agent loop with no step limit, no budget and no independent exit test runs until money, patience or the platform stops it.
    • Upkeep: The node's own work on one board: the decision on card length, the card format, the gate and the open tasks.
    • Weak-to-Strong Oversight: Open question: can weaker judges, human or model, reliably oversee agents stronger than themselves? What is known and what is not.
